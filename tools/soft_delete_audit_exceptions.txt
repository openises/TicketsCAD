# Soft-delete audit exceptions — tools/soft_delete_audit.php
#
# That gate finds every SELECT that reads `ticket` (directly, or via a
# resolvable $where-style variable) without a `deleted_at` exclusion term
# anywhere it can find one, and fails the suite on anything not listed here.
#
# FORMAT   path:line | reason        (both required; a reason-less entry
#                                     fails the gate, same as
#                                     tools/doc_nav_label_exceptions.txt)
#
# Adding a line here is a claim that the finding is correct as written —
# either the read is a legitimate case that must still see deleted rows
# (Eric's own example: an incident-number collision check must see a
# deleted incident's number to avoid reissuing it), or the tool's resolver
# genuinely cannot see a filter that is really there (a pre-wastebasket
# compatibility fallback that intentionally omits `deleted_at`; a downstream
# query that only ever executes after an earlier query in the same request
# has already excluded deleted rows). It is NOT the place to park a real
# gap that's inconvenient to fix — fix those.
#
# Every line must still match a real finding, or the gate treats it as
# STALE and fails — same discipline as the nav-label gate: a fixed site (or
# code that moved) makes its exception line meaningless, and a meaningless
# line left on file is how the next real regression hides in plain sight.
#
# ── CATEGORY A: legitimately needs to see deleted rows ──────────────────────
# Audit/history views and reference-integrity checks that operate ON
# deleted records (or must see them to stay consistent), not around them.
