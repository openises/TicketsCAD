# tools/csrf_coverage_audit.php -- verified false positives only.
#
# One entry per line:  "relative/path.php:LINE  reason".  The reason is mandatory (an entry with
# none fails the run) and must say WHY a forged request gains nothing. An entry that no longer
# matches a finding fails the run too, so this list cannot rot; when a line moves, fix the number.
#
# What belongs here, and what does not
#
#   A forged request is only dangerous if it makes the server change something the attacker wants
#   changed. Every entry below is a write the request cannot steer: housekeeping the server does
#   on its own schedule when any request happens to arrive (a lazy sweep, a purge of expired rows,
#   a status stamp), a cache refilled from an upstream answer, a token the response hands back to
#   a caller who -- being cross-site -- cannot read the response, or an idempotent registration
#   keyed by a secret the client generated. NONE of them is "a state change we have decided not to
#   protect": every endpoint that changes state because the CALLER asked it to has a csrf check, and
#   the first run of this gate found seven such endpoints that did not (api/organizations.php,
#   api/rbac.php, api/comm-identifiers.php, api/training.php, api/facility-capacity.php,
#   api/owntracks-config.php's three GET actions, api/inbound-calls.php's heartbeat) -- those were
#   FIXED, not baselined. If you are tempted to add a write here that a user's click causes, fix
#   the endpoint instead.
